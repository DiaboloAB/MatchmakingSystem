# Data Management

This project does **not** rely on static data samples or external datasets. Instead, it utilizes a **Simulator Script (`/sim`)** or manual client connection.

## No Static Data Samples

You will not find `.json` or `.csv` data samples in this repository. This is an intentional design choice for the following reasons:

1.  **Dynamic Generation**: The system is designed to test data *flow* and *recovery*. Static data cannot easily simulate the behavior of a live system with real player.
2.  **Volume Requirements**: To satisfy the need for high-volume data flux, the `sim` component generates hundreds of events per minute, simulating a live player population.
3.  **Stateful Evolution**: Player MMR and match history evolve over time based on simulated game outcomes. A static dataset would be a snapshot, whereas the simulator provides a living environment.

## The Simulator (`/sim`)

The `sim` directory contains the engine responsible for generating all system data.

You can run the simulator with `cargo run -p sim`, by default the simulator will spawn 50 players, with 80% of them existing account in the database.

### How it works:
-   **Player Agents**: Each simulated player is an independent asynchronous task running a state machine.
-   **Behavioral Modeling**: Players exhibit realistic behaviors:
    -   Connecting and disconnecting at random intervals.
    -   Queuing for games.
    -   Varying reaction times for game confirmations.
    -   Intentional AFK behavior (failing to confirm).
    -   Intentional paquet drop (simulating network issues).
-   **Session Churn**: Players play a random number of games (1-8) before disconnecting, creating a constant churn of data.

## Data Persistence

All the information about players and match results is stored in a SQLite database (`app_database.db`) using `sqlx`. The database schema includes tables for:
-   **Players**: Player ID, MMR, rank, ...
-   **Matches**: Match ID, team IDs, outcomes, and timestamps.

## How to Generate Data

To see the system in action and generate your own data flow:

1.  Ensure the server is running: `just run-server`
2.  Start the simulator: `just run-sim`
3.  Open the dashboard: `just run-dashboard`

The dashboard will immediately begin displaying the live data flux generated by the simulator.
